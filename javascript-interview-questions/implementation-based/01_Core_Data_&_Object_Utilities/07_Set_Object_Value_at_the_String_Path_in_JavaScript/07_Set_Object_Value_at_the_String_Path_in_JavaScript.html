Set Object Value at the String Path in JavaScript

Given an object, a path, and a value — update the object at that path. This is a polyfill for Lodash's _.set() and the opposite of _.get(). It's a key tool for config handling, API responses, and form state management.

Difficulty: ⭐⭐⭐ Category: Object Mutation Frequency: Medium #object #set #lodash #polyfill #recursion

The question

Restate what the interviewer is really asking before you write code.

  • Take an object, a path (string or array), and a value.
  • Set the value at that path, creating intermediate objects/arrays as needed.
  • Support both dot notation and bracket notation in the path.
Input
const obj = { a: [{ b: { c: 3 } }] };
set(obj, 'a[0].b.c', 4);
Output
obj.a[0].b.c === 4  // true

How the question is asked

The same problem can enter from different doors.

A

Direct polyfill request

"Write a polyfill for lodash's _.set()."

The interviewer wants to see you handle path normalization, recursive object creation, and value assignment. This is harder than _.get() because you need to create intermediate structures.

B

Progressive complexity

"Set a value in a nested object." → "Now with a string path." → "Create missing paths automatically." → "Handle arrays too."

The interviewer ramps up complexity. Each level builds on the previous.

How to answer, step by step

The strongest answer follows this progression.

1

Clarify the question

"Should I create intermediate objects/arrays if the path doesn't exist? Or should I throw an error?"

Almost always, the answer is "create them automatically." This is the key design decision — lodash's _.set() creates missing paths.

2

Path normalization

"First, convert the path into an array of keys — same as the _.get() approach."

// "a[0].b.c" → ["a", "0", "b", "c"]
// ['a', '0', 'b', 'c'] → ["a", "0", "b", "c"]

if (typeof path === 'string') {
  pathArr = path.replace('[', '.').replace(']', '').split(".");
}
3

The recursive helper

"The helper walks the path recursively. At each step, it checks if the current key exists — if not, it creates an array or object based on the next key."

const helper = (obj, path, value) => {
  let [current, ...rest] = path;

  if (rest.length > 0) {
    // More keys to traverse
    if (!obj[current]) {
      // Key doesn't exist: create array or object
      const isNumber = `${+rest[0]}` === rest[0];
      obj[current] = isNumber ? [] : {};
    }

    if (typeof obj[current] !== 'object') {
      // Current value is a primitive: replace it
      const isNumber = `${+rest[0]}` === rest[0];
      obj[current] = helper(isNumber ? [] : {}, rest, value);
    } else {
      // Current value is an object: recurse
      obj[current] = helper(obj[current], rest, value);
    }
  } else {
    // Last key: assign the value
    obj[current] = value;
  }

  return obj;
};
ⓘ Array vs Object detection

The trick `${+rest[0]}` === rest[0] checks if the next key is a numeric string. If it is, we create an array (since numeric keys indicate array indices). Otherwise, we create an object.

4

Write the full implementation

A. The set function
const set = (obj, path, value) => {
  let pathArr = path;

  if (typeof path === 'string') {
    pathArr = path.replace('[', '.').replace(']', '').split(".");
  }

  helper(obj, pathArr, value);
};
B. Test it
const abc = {
  a: { b: { c: [1, 2, 3] }, d: { a: "hello" } }
};

const instance1 = JSON.parse(JSON.stringify(abc));
set(instance1, 'a.b.c', 'learnersbucket');
console.log(instance1.a.b.c); // "learnersbucket"

const instance2 = JSON.parse(JSON.stringify(abc));
set(instance2, 'a.b.c[1]', 'learnersbucket');
console.log(instance2.a.b.c[1]); // "learnersbucket"

const instance3 = JSON.parse(JSON.stringify(abc));
set(instance3, 'a.b.c[3]', 'learnersbucket');
console.log(instance3.a.b.c[3]); // "learnersbucket" (creates index 3)

const instance4 = JSON.parse(JSON.stringify(abc));
set(instance4, 'a.c.d[0]', 'learnersbucket');
console.log(instance4.a.c.d[0]); // "learnersbucket" (creates entire path)

const object = { a: [{ b: { c: 3 } }] };
set(object, 'a[0].b.c', 4);
console.log(object.a[0].b.c); // 4

set(object, ['x', '0', 'y', 'z'], 5);
console.log(object.x[0].y.z); // 5
5

Close with edge cases and complexity

"A few edge cases — this method overrides existing values, creates intermediate structures, and mutates the original object."

⚠ Mutates the original object

Unlike _.get() which is read-only, _.set() mutates the object in place. If you want immutability, you'd need to deep-clone first.

✓ Overwrites existing values
const obj = { a: { b: 1 } };
set(obj, 'a.b', 2);
console.log(obj.a.b); // 2 (overwritten)
ⓘ Time & space complexity
  • Time: O(n) where n is the path depth.
  • Space: O(d) for the call stack where d is the path depth, plus any new objects created.

Key insights

  • Complements _.get() — together they handle reading and writing nested properties.
  • Auto-creates paths — if a.b.c doesn't exist, it builds the entire chain.
  • Array vs object detection is key — numeric next-key means create an array, otherwise an object.
  • Recursive decomposition — destructure [current, ...rest] to process one key at a time.
  • Mutates in place — be aware this modifies the original object.
  • Useful for config handling, API responses, and form state management.

Takeaway

By creating a polyfill for Lodash's _.set(), we learn how to handle dynamic paths for nested objects, safely mutate deeply nested values, and build recursive utilities for object manipulation. This complements the _.get() polyfill and is crucial for config handling, API responses, and form state management.
