Deep Flatten Object in JavaScript

Given a nested object with objects, arrays, and primitive values, flatten it into a new object where keys represent the full dot-notation path. Below is how to answer it step by step.

Difficulty: ⭐⭐ Category: Object Operations Frequency: Medium #object #flatten #recursion #deep

The question

Restate what the interviewer is really asking before you write code.

  • Flatten a nested object into a single-level object with dot-notation keys.
  • Support objects, arrays, and primitive values at any nesting depth.
  • Array indices become part of the key (e.g., C.Q.0, C.Q.1).
Input
{
  A: "12",
  B: 23,
  C: {
    P: 23,
    O: { L: 56 },
    Q: [1, 2]
  }
}
Output
{
  "A": "12",
  "B": 23,
  "C.P": 23,
  "C.O.L": 56,
  "C.Q.0": 1,
  "C.Q.1": 2
}

How the question is asked

The same problem can enter from different doors. Recognise the entry point and pick the right approach.

A

Direct implementation request

"Write a function that flattens a nested object into dot-notation keys."

The interviewer gives you the full spec upfront. This is common when they want to see your recursion and type-checking skills in action.

What to do: Clarify the types you need to handle (objects, arrays, primitives). Then walk through your approach: type checking with Object.prototype.toString.call() or typeof + Array.isArray(). Show pseudocode before coding.

B

Progressive complexity

"Flatten this object." → "Now handle arrays." → "What about deeply nested objects?" → "Can you make it cleaner?"

The interviewer starts simple and ramps up complexity. Each answer becomes the baseline for the next question. This tests how you adapt under pressure.

What to do: Answer each level completely before moving on. Don't jump ahead. Let them lead.

Level 1
// "Flatten this object"
{ a: 1, b: { c: 2 } }
→ { "a": 1, "b.c": 2 }

// Simple recursion with dot concatenation
Level 2
// "Now handle arrays"
{ a: 1, b: { c: [2, 3] } }
→ { "a": 1, "b.c.0": 2, "b.c.1": 3 }

// Array indices become part of the key
Level 3
// "What about empty arrays or null values?"
{ a: [], b: null }
→ { "a": [], "b": null }

// Decide: skip or preserve?
Level 4
// "Can you make it cleaner?"
// Convert arrays to objects before recursion
// Avoids separate array handling logic

// Mention the spread trick: { ...arr }

How to answer, step by step

Regardless of how the question is asked, the strongest answer follows this progression. Each step below shows you what to say, what to write, and why it matters.

1

Clarify the question

"Before I start — should I handle only objects and primitives, or also arrays? And should array indices appear as part of the flattened key?"

Asking this shows you think before you code. You're confirming the exact contract: objects only, or objects + arrays. The answer determines whether you need special array handling.

2

Show type-checking awareness

"First, I need to distinguish between objects, arrays, and primitives. I can use Object.prototype.toString.call() or typeof + Array.isArray()."

This is the foundation. You need to know what you're dealing with before recursing.

// Method 1: Object.prototype.toString.call()
const type = Object.prototype.toString.call(value);
type === "[object Object]"  // plain object
type === "[object Array]"   // array

// Method 2: typeof + Array.isArray()
typeof value === "object" && value !== null  // object or array
Array.isArray(value)                         // specifically an array
ⓘ Which to use?

Object.prototype.toString.call() is more reliable across different contexts (e.g., iframes, cross-realm objects). typeof + Array.isArray() is more readable and commonly used in interviews. Know both.

3

Show a clever trick: arrays to objects

"A clean trick: instead of handling arrays separately, convert them to objects using spread, then recurse uniformly."

// Array
const arr = [1, 2, 3];

// Spread into object: { '0': 1, '1': 2, '2': 3 }
const { ...arrAsObj } = arr;

// Now you can recurse the same way as regular objects
✓ Why this works

Arrays in JavaScript are objects with numeric keys. Spreading an array into an object gives you { '0': val, '1': val, ... } — which you can recurse into just like a regular object. This eliminates the need for separate array handling logic.

4

Write the full implementation

"Now for the proper implementation — a recursive function with type checking."

This is the main event. You're showing you can build it from scratch, handle all types, and manage the key path correctly.

A. Pseudocode

Before writing code, think in plain English:

function flatten(obj, prefix):
    create an empty result object

    for each key in obj:
        get the value
        create newKey = prefix ? prefix + "." + key : key

        if value is an object (not null, not array):
            // recurse: flatten the sub-object
            merge flatten(value, newKey) into result

        else if value is an array:
            // convert to object and recurse
            merge flatten({ ...value }, newKey) into result

        else:
            // primitive value: add to result
            result[newKey] = value

    return result
B. Building the code — line by line

Now translate the pseudocode into JavaScript:

const flatten = (obj, prefix) => {

Line 1 — function signature. Takes the object to flatten and an optional prefix for building the key path. The prefix starts as undefined and accumulates as we recurse deeper.

  let output = {};

Line 2 — accumulator. We build a new object instead of mutating the input. Each recursive call returns its own flattened object, which we merge into this one.

  for (let k in obj) {

Line 3 — iterate every key. A for...in loop over the object's enumerable properties. We need to check every value because some are objects (recurse), some are arrays (convert + recurse), and some are primitives (keep as-is).

    let val = obj[k];

Line 4 — get the value. We'll check its type in the next steps.

    const type = Object.prototype.toString.call(val);

Line 5 — type check. This gives us a reliable string like "[object Object]", "[object Array]", or "[object Number]". It's more reliable than typeof for distinguishing objects from arrays.

    if (type === "[object Object]") {

Line 6 — object branch. If it's a plain object, we recurse into it.

      const newKey = prefix ? prefix + "." + k : k;
      const newObj = flatten(val, newKey);
      output = { ...output, ...newObj };

Lines 7-9 — recurse and merge. Build the new key path by appending the current key to the prefix. Recurse on the sub-object. Spread the result into our output.

    } else if (type === "[object Array]") {

Line 10 — array branch. Arrays need special handling — we iterate each element by index.

      for (let i = 0; i < val.length; i++) {
        const newKey = prefix ? prefix + "." + k + "." + i : k + "." + i;
        output = { ...output, [newKey]: val[i] };
      }

Lines 11-13 — iterate array elements. For each array element, we append both the key and the index to create the full path. For example, C.Q.0 means: key C, then Q, then index 0.

    } else {
      const newKey = prefix ? prefix + "." + k : k;
      output = { ...output, [newKey]: val };
    }

Lines 14-16 — primitive base case. If it's a string, number, boolean, or null, we just add it directly to the output with its full key path. No recursion needed.

  }
  return output;
};
C. The final version — clean

Putting it all together:

const flatten = (obj, prefix) => {
  let output = {};

  for (let k in obj) {
    let val = obj[k];
    const type = Object.prototype.toString.call(val);

    if (type === "[object Object]") {
      const newKey = prefix ? prefix + "." + k : k;
      const newObj = flatten(val, newKey);
      output = { ...output, ...newObj };
    } else if (type === "[object Array]") {
      for (let i = 0; i < val.length; i++) {
        const newKey = prefix ? prefix + "." + k + "." + i : k + "." + i;
        output = { ...output, [newKey]: val[i] };
      }
    } else {
      const newKey = prefix ? prefix + "." + k : k;
      output = { ...output, [newKey]: val };
    }
  }

  return output;
};
D. Test it — verify the output

In an interview, walk through examples to prove it works:

const nested = {
  A: "12",
  B: 23,
  C: {
    P: 23,
    O: { L: 56 },
    Q: [1, 2]
  }
};

console.log(flatten(nested));
// {
//   "A": "12",
//   "B": 23,
//   "C.P": 23,
//   "C.O.L": 56,
//   "C.Q.0": 1,
//   "C.Q.1": 2
// }
E. The tricky part — key path building

Here's the detail that separates you from someone who memorized a solution:

// WRONG — forgetting the initial key
const newKey = prefix + "." + k;  // undefined + "." + k = "undefined.k"!

// RIGHT — check if prefix exists
const newKey = prefix ? prefix + "." + k : k;

// For arrays, you need BOTH the key AND the index
const newKey = prefix ? prefix + "." + k + "." + i : k + "." + i;
// Result: "C.Q.0" not just "Q.0" or "C.0"

Why this matters: The key path is the entire point of flattening. Get it wrong and you lose the structure. Always handle the prefix-undefined case, and for arrays, make sure you're building the full path.

5

Close with edge cases and complexity

"A couple of edge cases to consider — empty objects, circular references, and nested arrays within objects. The time complexity is O(n) where n is the total number of keys across all nesting levels."

✓ Empty objects and arrays
// Empty object — nothing gets added
flatten({ a: {}, b: 1 });
// { "b": 1 }

// Empty array — nothing gets added
flatten({ a: [], b: 1 });
// { "b": 1 }
✓ Null values
// null is typeof "object" but we handle it as a primitive
flatten({ a: null, b: { c: 2 } });
// { "a": null, "b.c": 2 }
⚠ Circular references

If the object has circular references, the recursion will never stop and you'll hit a stack overflow. In production, you'd need to track visited objects. Mention this proactively:

// This causes infinite recursion:
const a = {};
a.self = a;  // circular reference
flatten(a);  // → RangeError!
ⓘ Time & space complexity
  • Time: O(n) where n is the total number of leaf values (primitives) across all nesting levels. Every property is visited exactly once.
  • Space: O(n) for the result object, plus O(d) for the call stack where d is the maximum nesting depth.

Why it matters: This is the finishing move. Most candidates stop after writing the function. By proactively discussing edge cases, you show production thinking — you're not just solving a puzzle, you're writing code that needs to handle real-world data.

Approach 2: Convert arrays to objects (cleaner)

Instead of handling arrays separately, convert them into objects before recursing. This unifies the logic.

const flatten = (obj, prefix) => {
  let output = {};

  for (let k in obj) {
    let val = obj[k];
    const newKey = prefix ? prefix + "." + k : k;

    if (typeof val === "object") {
      if (Array.isArray(val)) {
        const { ...arrToObj } = val;  // spread array into object
        const newObj = flatten(arrToObj, newKey);
        output = { ...output, ...newObj };
      } else {
        const newObj = flatten(val, newKey);
        output = { ...output, ...newObj };
      }
    } else {
      output = { ...output, [newKey]: val };
    }
  }

  return output;
};
ⓘ Approach 1 vs Approach 2
  • Approach 1 uses Object.prototype.toString.call() and handles arrays with a separate loop. More explicit, easier to explain step by step.
  • Approach 2 uses typeof + Array.isArray() and converts arrays to objects with spread. Cleaner, less code, but the spread trick needs explanation.

Key insights

  • Know the entry point — direct implementation or progressive complexity — and pick the right approach.
  • Always clarify first — whether to handle arrays is the key constraint.
  • Type checking is the foundation — know the difference between typeof, Array.isArray(), and Object.prototype.toString.call().
  • The arrays-to-objects trick shows lateral thinking and reduces code complexity.
  • Key path building is where most bugs live — always handle the prefix-undefined case.
  • End with edge cases and complexity — this separates a good answer from a great one.
  • Know both approaches — start with whichever you're more comfortable with, and switch if the interviewer asks.

Takeaway

Deep flattening objects is useful for config management (flatten nested settings into dot-notation), form data processing, and database queries (NoSQL often uses dot notation). The recursive approach improves understanding of nested data structures, type checking, and object/array handling in JavaScript.
