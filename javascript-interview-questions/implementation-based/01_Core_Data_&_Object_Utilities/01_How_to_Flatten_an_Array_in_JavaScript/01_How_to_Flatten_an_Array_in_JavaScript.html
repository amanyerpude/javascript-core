How to Flatten an Array in JavaScript

This question was asked in Meta's frontend interview. Flattening means converting nested sub-arrays (N-dimensional) into a single one-dimensional array. Below is how to answer it step by step.

Company: Meta Difficulty: ⭐⭐ Category: Array Operations Frequency: High #array #flatten #flatMap #polyfill

The question

Restate what the interviewer is really asking before you write code.

  • Merge nested arrays into a single flat array.
  • Support flattening to one level, a specified depth, and infinite depth.
  • Be ready to discuss native methods (flat, flatMap) and write a custom polyfill.
Input
[[[1, [1.1]], 2, 3], [4, 5]]
Output
[1, 1.1, 2, 3, 4, 5]

How the question is asked

The same problem can enter from different doors. Recognise the entry point and pick the right approach.

A

Direct polyfill request

"Write a polyfill for Array.prototype.flat()."

The interviewer skips the problem statement and goes straight to implementation. This is common when they already know you know the native API — they want to see you build it from scratch.

What to do: Skip the native explanation. Go straight to clarifying depth ("Should I support a depth argument?"), then write the pseudocode, then the polyfill. Show your work: pseudocode → code → test → edge cases.

B

Progressive complexity

"Given this array, flatten it." → "Now with depth." → "Now handle sparse arrays." → "What about performance?"

The interviewer starts simple and ramps up complexity. Each answer you give becomes the baseline for the next question. This is the most common pattern — it tests how you adapt under pressure.

What to do: Answer each level completely before moving on. Don't jump ahead — if they ask for depth, don't mention performance yet. Let them lead.

Level 1
// "Flatten this array"
[[1, [2]], [3, [4]]]
→ [1, 2, 3, 4]

// Use flat() or a simple recursive function
Level 2
// "Now support a depth parameter"
flattenDepth([[1, [2]], [3, [4]]], 1)
→ [1, [2], 3, [4]]

// Add depth tracking to your function
Level 3
// "What about sparse arrays?"
[1, , [2, , 3]]
→ [1, 2, 3]  // native flat() drops empty slots

// Decide: match native or preserve holes?
Level 4
// "What's the time complexity?"
// O(n) over all elements
// Recursion depth = nesting depth

// Mention concat vs push tradeoff

How to answer, step by step

Regardless of how the question is asked, the strongest answer follows this progression. Each step below shows you what to say, what to write, and why it matters.

1

Clarify the question

"Before I start coding — flattening means converting nested sub-arrays into a single one-dimensional array, right? Should I flatten fully, or do you want me to support a specific depth argument?"

Asking this shows you think before you code. You're confirming the exact contract: one level, custom depth, or infinite depth. The interviewer will almost always say "support a depth parameter" or "flatten infinitely" — and now you know the constraint before touching the keyboard.

2

Show the native approach

"ES2019 gives us flat() and flatMap(). flat() flattens one level by default, takes a depth argument, and even accepts Infinity."

This is the baseline. You're proving you know the language before reimplementing anything.

[1, 2, [3, 4]].flat();                       // [1, 2, 3, 4]
[1, 2, [3, 4], [[5]]].flat(2);               // [1, 2, 3, 4, 5]
[[[1, [1.1]], 2, 3], [4, 5]].flat(Infinity); // [1, 1.1, 2, 3, 4, 5]
ⓘ flatMap — map + flatten in one step

flatMap() runs a mapping function on each element, then flattens the result by one level. It's equivalent to .map(fn).flat(1) but faster because it avoids creating an intermediate array.

// map() returns nested arrays
['hello world', 'foo bar'].map(s => s.split(' '));
// [["hello", "world"], ["foo", "bar"]]

// flatMap() returns a flat array
['hello world', 'foo bar'].flatMap(s => s.split(' '));
// ["hello", "world", "foo", "bar"]

Why it matters: The interviewer's real question is "do you know this exists?" If you jump straight to a polyfill without mentioning flat(), you look like you don't know modern JavaScript. Native first, always.

3

Show a clever one-liner

"A quick trick if the interviewer asks for a one-liner: convert to string and split."

const flatten = (arr) => arr.toString().split(',').map(Number);

flatten([[1, [1.1]], 2, [3, 4]]);
// [1, 1.1, 2, 3, 4]
⚠ Important caveat

This only works for arrays of numbers. It converts everything to strings via toString(), then parses back with Number. It breaks on: strings containing commas (["a,b"] becomes ["a", "b"]), objects ([{}, {}]), null, undefined, or nested objects. Don't use this in production — it's an interview flex only.

Why it matters: This shows lateral thinking. You're not going to ship this to production, but it demonstrates you can approach the problem from multiple angles. Interviewers notice this. It buys you time and credibility before you write the real implementation.

4

Write the full polyfill

"Now for a proper implementation — a recursive loop with a depth parameter."

This is the main event. You're showing you can build it from scratch, handle depth correctly, and think about edge cases.

A. Pseudocode

Before writing code, think in plain English. The algorithm does this:

function flattenDepth(arr, depth):
    create an empty result array

    for each item in arr:
        if item is an array AND depth > 0:
            // recurse: flatten the sub-array, reducing depth by 1
            // and spread the results into our result array
            push all elements of flattenDepth(item, depth - 1) into result
        else:
            // base case: item is not an array, or we've exhausted depth
            // push it as-is (keeps the sub-array intact)
            push item into result

    return result

This pseudocode captures the two core ideas: recursion (call yourself on sub-arrays) and depth tracking (decrement depth each level, stop when it hits 0).

B. Building the code — line by line

Now translate the pseudocode into JavaScript. Here's the final version, with every line explained:

const flattenDepth = (arr, depth = 1) => {

Line 1 — function signature. Takes two arguments: the array to flatten, and a depth parameter defaulting to 1. The default matches native flat() behavior — flatten one level unless told otherwise.

  const result = [];

Line 2 — accumulator. We build a new array instead of mutating the input. In an interview, say: "I'm avoiding mutation so the caller's data isn't modified."

  for (const item of arr) {

Line 3 — iterate every element. A simple for...of loop over the input array. We need to check every element because some are arrays (recurse) and some are values (keep as-is).

    if (Array.isArray(item) && depth > 0) {

Line 4 — the decision point. Two conditions must both be true to recurse: (1) the item is actually an array, and (2) we still have depth budget left. This is the circuit breaker that stops infinite recursion.

      result.push(...flattenDepth(item, depth - 1));

Line 5 — the recursive call. We call flattenDepth on the sub-array, passing depth - 1. The result is a flat array, so we use spread ... to push each element individually into result. This is what makes the function recursive.

    } else {

Line 6 — base case. Either the item isn't an array (it's a primitive), or we've exhausted our depth budget. We stop recursing here.

      result.push(item);

Line 7 — keep as-is. Push the item directly. If depth is 0, sub-arrays stay intact — not spread, not flattened, just passed through. This matches native flat(0) behavior exactly.

    }
  }
  return result;
};
C. The final version — clean

Putting it all together:

const flattenDepth = (arr, depth = 1) => {
  const result = [];
  for (const item of arr) {
    if (Array.isArray(item) && depth > 0) {
      result.push(...flattenDepth(item, depth - 1));
    } else {
      result.push(item);
    }
  }
  return result;
};
D. Test it — verify depth semantics

In an interview, walk through examples to prove it works:

// depth 1 — only flattens the first level
flattenDepth([[1, [2]], [3, [4]]], 1);
// → [1, [2], 3, [4]]    ← sub-arrays stay at depth 1

// depth 2 — goes one level deeper
flattenDepth([[1, [2]], [3, [4]]], 2);
// → [1, 2, 3, 4]        ← fully flattened

// depth Infinity — goes all the way
flattenDepth([[[1, [2]]]], Infinity);
// → [1, 2]               ← no nesting left
E. The classic bug — concat vs push

Here's the detail that separates you from someone who memorized a solution:

// WRONG — using concat
const flattenBroken = (arr, depth = 1) => {
  return arr.reduce((result, item) => {
    if (Array.isArray(item) && depth > 0) {
      return result.concat(flattenBroken(item, depth - 1));
    }
    return result.concat(item);  // ← BUG: concat spreads arrays even at depth 0
  }, []);
};

flattenBroken([[1, [2]], [3]], 1);
// → [1, 2, 3]    ← WRONG! Should be [1, [2], 3]

Why this breaks: Array.concat(item) automatically spreads item if it's an array. So when depth is 0 and the item is [2], concat spreads it into 1, 2 instead of keeping it as [2]. The depth parameter becomes meaningless.

The fix: Use result.push(item) instead. push does not auto-spread — it adds the item as-is. If the item is an array and depth is 0, it stays an array.

5

Close with edge cases and complexity

"A couple of edge cases to consider — sparse arrays with empty slots, non-array values in the input, and the time complexity is O(n) across all elements. The recursion depth scales with the nesting depth."

✓ Sparse arrays

Our for...of loop skips empty slots, matching native flat() behavior:

// Sparse array: empty slots between values
const sparse = [1, , [2, , 3]];
flattenDepth(sparse, Infinity);
// → [1, 2, 3]    ← empty slots dropped, same as flat()

// If you need to PRESERVE empty slots, use a traditional for loop:
for (let i = 0; i < arr.length; i++) {
  // arr[i] is undefined for empty slots — you can push it
}
✓ Non-array values in input
// Primitives, objects, null — all pass through untouched
flattenDepth([1, 'hello', null, [2, [3]]], Infinity);
// → [1, 'hello', null, 2, 3]

// Nested objects are NOT flattened (they're not arrays)
flattenDepth([{ a: 1 }, [2]], Infinity);
// → [{ a: 1 }, 2]
⚠ Stack overflow with deep nesting

The recursive version creates one call frame per nesting level. With Infinity depth on a deeply nested array, you can hit the JS call stack limit (~10,000–15,000 frames in most engines):

// This will throw: "Maximum call stack size exceeded"
const deep = Array(20000).fill(null).reduce((acc) => [acc], 0);
flattenDepth(deep, Infinity);  // → RangeError!

// Mitigation: use an iterative approach with an explicit stack
function flattenIterative(arr) {
  const stack = [...arr];
  const result = [];
  while (stack.length) {
    const item = stack.pop();
    if (Array.isArray(item)) {
      stack.push(...item);
    } else {
      result.unshift(item);
    }
  }
  return result;
}

In practice, nesting deeper than a few hundred levels is rare. Mention this proactively — it shows you think about production limits, not just algorithmic correctness.

ⓘ Time & space complexity
  • Time: O(n) where n is the total number of elements across all nesting levels. Every element is visited exactly once.
  • Space: O(n) for the result array, plus O(d) for the call stack where d is the nesting depth.

Why it matters: This is the finishing move. Most candidates stop after writing the function. By proactively discussing edge cases, you show production thinking — you're not just solving a puzzle, you're writing code that needs to handle real-world inputs.

Alternative: reduce + push

A common interview follow-up: "Can you write it with reduce?" Here's a working version that avoids the concat bug.

const flattenDepth = (arr, depth = 1) => {
  return arr.reduce((result, item) => {
    if (Array.isArray(item) && depth > 0) {
      result.push(...flattenDepth(item, depth - 1));
    } else {
      result.push(item);  // push, NOT concat
    }
    return result;
  }, []);
};
ⓘ for...of vs reduce — which to use?

Both work identically. The for...of version is arguably more readable for beginners. The reduce version is more "functional" and often expected in interviews. Know both — start with whichever you're more comfortable with, and switch if the interviewer asks.

Key insights

  • Know the entry point — direct polyfill or progressive complexity — and pick the right approach.
  • Always clarify first — depth requirement is the key constraint.
  • Start with native — it shows you know modern JavaScript before reinventing anything.
  • A clever one-liner buys you time and shows lateral thinking — even if it's not production-ready.
  • The polyfill is where you prove you understand recursion, depth control, and edge cases.
  • Know the concat vs push distinction — this is what separates deep understanding from memorization.
  • End with edge cases and complexity — this is what separates a good answer from a great one.

Takeaway

Flattening arrays is both a common interview problem and a practical skill. In modern browsers use flat / flatMap; when compatibility is required, ship a recursive polyfill. This problem reinforces array methods, recursion, and iteration strategies in JavaScript.
