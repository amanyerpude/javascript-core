Get Object Value from String Path in JavaScript

Implement a method that takes an object and a string path (or array of strings) and returns the value at that path. This is a polyfill for lodash._get() — one of the most commonly used utility functions.

Difficulty: ⭐⭐ Category: Object Traversal Frequency: High #object #path #lodash #polyfill

The question

Restate what the interviewer is really asking before you write code.

  • Take an object and a dot/bracket path string (e.g., "a.b.c[0]").
  • Return the value at that path, or undefined if the path doesn't exist.
  • Support both dot notation (a.b.c) and bracket notation (a.b.c[0]).
Input
const obj = { a: { b: { c: [1,2,3] } } };
get(obj, 'a.b.c[1]')
Output
2

How the question is asked

The same problem can enter from different doors.

A

Direct polyfill request

"Write a polyfill for lodash's _.get()."

The interviewer wants to see you build it from scratch. Start by clarifying the path format (dot notation, bracket notation, or both), then walk through normalization and traversal.

B

Progressive complexity

"Get a value from a nested object." → "Now with a string path." → "Handle bracket notation." → "What about arrays?"

The interviewer ramps up complexity. Answer each level before moving on.

How to answer, step by step

The strongest answer follows this progression.

1

Clarify the question

"Should the path support both dot notation and bracket notation? And should I handle array indices as part of the path?"

This confirms the contract. The interviewer will usually say "handle both."

2

Explain path normalization

"First, I need to normalize the path — convert it into an array of keys."

// Input path: "a.b.c[0]"
// After normalization: ["a", "b", "c", "0"]

// Steps:
// 1. If path is an array, join with "."
// 2. Remove "[", "]", and "." characters
// 3. Extract the remaining characters as individual keys
ⓘ Why normalize?

Path strings can be "a.b.c", "a.b.c[0]", or ["a", "b", "c"]. Normalizing converts all formats into a uniform array of keys that we can iterate over.

3

Traverse with reduce

"Once I have the keys, I use reduce to walk the object step by step."

// reduce walks the path:
// Start: obj
// Step 1: obj["a"]      → { b: { c: [1,2,3] } }
// Step 2: obj["a"]["b"]  → { c: [1,2,3] }
// Step 3: obj["a"]["b"]["c"] → [1,2,3]
// Step 4: obj["a"]["b"]["c"]["0"] → 1

const value = exactPath.reduce((source, path) => source[path], obj);
4

Write the full implementation

"Here's the complete get function — a polyfill for lodash._get()."

A. The implementation
const get = (obj, path) => {
  // if path is not a string or array of string
  if (path === '' || path.length == 0) return undefined;

  // if path is an array, concatenate it and form a string
  if (Array.isArray(path)) path = path.join('.');

  // filter out brackets and dots
  let exactPath = [];
  for (let i = 0; i < path.length; i++) {
    if (path[i] !== '[' && path[i] !== ']' && path[i] !== '.') {
      exactPath.push(path[i]);
    }
  }

  // traverse the object
  const value = exactPath.reduce((source, path) => source[path], obj);

  // return value or undefined
  return value ? value : undefined;
};
B. Walk through each line

Line 1 — guard clause. If the path is empty or has no length, return undefined immediately.

Line 2 — array path. If the path is an array like ["a", "b", "c"], join it with dots to form "a.b.c".

Lines 3-7 — normalize. Loop through the path string and extract only alphanumeric characters, removing [, ], and ..

Line 8 — traverse. Use reduce to walk the object. Each iteration accesses the next key in the chain.

Line 9 — return. Return the value, or undefined if the chain broke at any point.

C. Test it
const obj = { a: { b: { c: [1,2,3] } } };

console.log(get(obj, 'a.b.c'));          // [1,2,3]
console.log(get(obj, 'a.b.c.0'));        // 1
console.log(get(obj, 'a.b.c[1]'));       // 2
console.log(get(obj, ['a','b','c','2'])); // 3
console.log(get(obj, 'a.b.c[3]'));       // undefined
console.log(get(obj, 'a.c'));            // undefined
5

Close with edge cases and complexity

"A few edge cases — empty path, missing intermediate keys, and the difference between null and undefined."

✓ Missing intermediate keys
get({ a: { b: 1 } }, 'a.x.y');
// undefined — "x" doesn't exist, chain breaks
✓ Empty path
get({ a: 1 }, '');
// undefined — guard clause catches this
ⓘ Time & space complexity
  • Time: O(n) where n is the length of the path (number of keys to traverse).
  • Space: O(n) for the normalized path array.
⚠ Return value caveat

The current implementation uses return value ? value : undefined, which treats 0, "", and false as falsy. A more robust check would be return value !== undefined ? value : undefined.

Key insights

  • This mimics Lodash's _.get() behavior — one of the most used utility functions in JavaScript.
  • Path normalization is the key challenge — converting "a.b.c[0]" into ["a", "b", "c", "0"].
  • reduce is the natural fit for sequential traversal — each step passes the current value to the next.
  • Works for both dot notation and bracket notation paths.
  • Safely handles nested arrays (via index access) and objects.
  • Returns undefined if path is invalid, preventing runtime errors like Cannot read property of undefined.
  • Useful for config files, APIs, form data, and deeply nested JSON.

Takeaway

By building a polyfill for _.get(), we learn about dynamic property access, string parsing and normalization, and safe object traversal with reduce. This pattern is extremely useful for config files, APIs, form data, and deeply nested JSON.
