Array Iterator Method in JavaScript

Create a custom iterator that accepts an array and returns methods to get the next value and check if iteration is complete. This tests your understanding of closures, state management, and iteration protocols.

Difficulty: ⭐⭐ Category: Iteration & Closures Frequency: Medium #iterator #closure #array #interview

The question

Restate what the interviewer is really asking before you write code.

  • Build a helper function that takes an array and returns an iterator object.
  • The iterator must have a next() method that returns the next element (or null when exhausted).
  • It must also have a done() method that returns a boolean indicating if iteration is complete.
Input
helper([1, 2, "hello"])
Output (sequence)
iterator.next()  // 1
iterator.next()  // 2
iterator.done()  // false
iterator.next()  // "hello"
iterator.done()  // true
iterator.next()  // null

How the question is asked

The same problem can enter from different doors. Recognise the entry point and pick the right approach.

A

Direct implementation request

"Write a function that creates an iterator for an array."

The interviewer gives you the full spec upfront. They want to see your ability to use closures for state management.

What to do: Start by explaining that you'll use a closure to capture the array and an index. Then write the implementation step by step. Mention that this mimics the native iterator protocol.

B

Progressive complexity

"Make an iterator." → "Now add a done check." → "What if the array is empty?" → "Can you do it with generators?"

The interviewer starts simple and ramps up complexity. Each answer becomes the baseline for the next question.

What to do: Answer each level completely before moving on. Let them lead.

Level 1
// "Make an iterator"
const helper = (arr) => {
  let index = 0;
  return {
    next: () => arr[index++] ?? null
  };
};
Level 2
// "Now add a done check"
return {
  next: () => index < arr.length ? arr[index++] : null,
  done: () => index >= arr.length
};
Level 3
// "Empty array?"
helper([]).next()   // null
helper([]).done()   // true

// Works — index starts at 0, immediately exhausted
Level 4
// "Can you do it with generators?"
function* gen(arr) {
  for (const item of arr) yield item;
}
// Closer to native iterator protocol

How to answer, step by step

Regardless of how the question is asked, the strongest answer follows this progression. Each step below shows you what to say, what to write, and why it matters.

1

Clarify the question

"Before I start — should next() return the value directly, or an object like { value, done }? And should it return null or undefined when exhausted?"

Asking this shows you think before you code. You're confirming the exact contract: return format (value vs. object) and exhaustion behavior (null vs. undefined). The interviewer will usually say "just return the value or null."

2

Explain the closure concept

"I'll use a closure to maintain state. The outer function captures the array and an index tracker, and the returned methods can access and modify that index across calls."

This is the foundation. You're proving you understand how closures preserve state between function invocations.

// Closure = function + its lexical environment
const helper = (array) => {
  // This variable lives in the closure
  // It persists across calls to next() and done()
  let nextIndex = 0;

  return {
    next: function () { /* can access array and nextIndex */ },
    done: function () { /* can access array and nextIndex */ }
  };
};
ⓘ Why closures?

Closures let you create private state. The nextIndex variable is not accessible from outside the returned object — only next() and done() can read or modify it. This is encapsulation without classes.

3

Design the state management

"The index starts at 0 and increments with each next() call. When it reaches the array length, we've exhausted the iterator."

// State transitions:
// Index 0 → return array[0], move to index 1
// Index 1 → return array[1], move to index 2
// ...
// Index n → return null (exhausted)
// done() returns true when index >= array.length
✓ Post-increment trick

Use array[nextIndex++] — this returns the current value then increments the index. It's a single expression that does both operations. If you used ++nextIndex (pre-increment), you'd skip the first element.

4

Write the full implementation

"Now for the proper implementation — a closure-based iterator with next() and done()."

A. Pseudocode
function helper(array):
    create index = 0

    return object with:
        next():
            if index < array.length:
                return array[index++]  // post-increment
            else:
                return null

        done():
            return index >= array.length
B. Building the code — line by line
const helper = (array) => {

Line 1 — function signature. Takes an array as input. We'll return an iterator object with next() and done() methods.

  let nextIndex = 0;

Line 2 — the state. This is the key. nextIndex lives in the closure — it persists across calls to next() and done(). Every time next() is called, it reads and increments this value.

  return {

Line 3 — return the iterator. We return an object, not the functions directly. This gives us a clean API: iterator.next(), iterator.done().

    next: function () {
      return nextIndex < array.length
        ? array[nextIndex++]
        : null;
    },

Lines 4-6 — the next() method. Two paths: if the index is within bounds, return the current element and increment (post-increment). Otherwise, return null to signal exhaustion.

    done: function () {
      return nextIndex >= array.length;
    }

Lines 7-9 — the done() method. Simply checks if we've reached or passed the end of the array. Returns a boolean.

  };
};
C. The final version — clean
const helper = (array) => {
  let nextIndex = 0;

  return {
    next: function () {
      return nextIndex < array.length
        ? array[nextIndex++]
        : null;
    },

    done: function () {
      return nextIndex >= array.length;
    }
  };
};
D. Test it — walk through the sequence
let iterator = helper([1, 2, "hello"]);

console.log(iterator.next()); // 1      (index: 0 → 1)
console.log(iterator.next()); // 2      (index: 1 → 2)
console.log(iterator.done()); // false  (index 2 < length 3)
console.log(iterator.next()); // "hello" (index: 2 → 3)
console.log(iterator.done()); // true   (index 3 >= length 3)
console.log(iterator.next()); // null   (exhausted)
E. The tricky part — post-increment vs. pre-increment
// POST-increment (correct): array[nextIndex++]
// Returns array[0], THEN increments nextIndex to 1
// First call returns 1 ✓

// PRE-increment (wrong): array[++nextIndex]
// Increments nextIndex to 1 first, THEN returns array[1]
// First call returns 2 ✗ (skips first element!)

Why this matters: This is a classic gotcha. The difference between i++ and ++i is subtle but critical. In an interview, mentioning this shows you understand evaluation order.

5

Close with edge cases and complexity

"A few edge cases — empty arrays, calling next() after exhaustion, and multiple iterators from the same array. Time complexity is O(1) per call, O(n) total."

✓ Empty array
const it = helper([]);
it.next(); // null (immediately exhausted)
it.done(); // true
✓ Calling next() after exhaustion
const it = helper([1]);
it.next(); // 1
it.next(); // null
it.next(); // null (safe to keep calling)
it.done(); // true
ⓘ Multiple iterators
const arr = [1, 2, 3];
const it1 = helper(arr);
const it2 = helper(arr);

it1.next(); // 1
it1.next(); // 2
it2.next(); // 1  ← independent iterator!

Each call to helper() creates a new closure with its own nextIndex. Iterators are independent.

ⓘ Time & space complexity
  • Time: O(1) per next() / done() call. O(n) total to iterate the full array.
  • Space: O(1) for the closure (just stores the array reference and index). O(n) if you collect all values into a new array.
⚠ Array mutation

If the array is mutated after creating the iterator, behavior is undefined:

const arr = [1, 2, 3];
const it = helper(arr);
it.next(); // 1
arr.push(4);  // mutation!
it.next();    // 2 (works, but the array changed)

In production, you'd want to freeze the array or copy it. Mention this proactively.

Alternative: ES6 Generators

Modern JavaScript provides generators (function*) as a built-in way to create iterators. This is closer to the native iterator protocol.

function* generatorHelper(array) {
  for (let item of array) {
    yield item;
  }
}

const iterator = generatorHelper([1, 2, "hello"]);

console.log(iterator.next().value); // 1
console.log(iterator.next().value); // 2
console.log(iterator.next().done);  // false
console.log(iterator.next().value); // "hello"
console.log(iterator.next().done);  // true
ⓘ Closure vs. Generator
  • Closure: Manual state management, more explicit, works in older environments. Shows you understand how iteration works under the hood.
  • Generator: Built-in yield keyword handles state automatically, matches the native iterator protocol, cleaner syntax. But it's "magic" — interviewers may want to see the closure version first.
⚠ Interview strategy

Always show the closure version first. It proves you understand the fundamentals. Then mention generators as an alternative — this shows you know modern JavaScript without skipping the basics.

Key insights

  • Closures are the foundation — the iterator's state lives in the closure, not in global variables or object properties.
  • Post-increment (i++) is essential — pre-increment skips the first element.
  • Return an object with methods, not bare functions — this gives a cleaner API and matches the native iterator protocol.
  • Empty arrays and post-exhaustion calls must be handled gracefully.
  • Multiple iterators from the same array are independent — each has its own closure.
  • Generators are the modern alternative — show them after the closure version to demonstrate range.
  • This question demonstrates encapsulation, state management, and iteration logic — three core JavaScript concepts in one problem.

Takeaway

Building a custom array iterator helps you understand how iteration works under the hood, practice closures and stateful functions, and compare closures vs. ES6 generators. This pattern is essential for mastering iterables, async iterables, and custom data structures in JavaScript.
